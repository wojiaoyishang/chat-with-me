Markdown、Replacement 与 Widget
================================================================================

Markdown
--------------------------------------------------------------------------------

``MarkdownRenderer`` 负责 GFM、Math、Highlight 和自定义 Directive。模型文本不能直接执行任意
HTML/脚本，渲染扩展要经过白名单组件。

Markdown 标签由稳定的 React 组件承载；流式只读标记、权限和任务原文通过当前渲染上下文
传入。回复结束不能更换段落、列表、表格、媒体或 replacement 的组件类型，否则会卸载
已有原生视频，丢失播放位置、音量与代码复制状态。真正改变媒体 URL 时才创建新播放器。

显式音频与视频
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

音频使用 ``![生成语音](cwm://artifact/实际附件ID){type=audio}``，视频继续使用
``{type=video}``。标记必须紧接图片语法；普通图片、转义标记、代码与原生 HTML 不会
变成播放器。两者复用 ``createMediaDirective``，保留相邻正文和混合媒体的顺序。

``ResourceAudio`` 经统一虚拟地址和授权资源解析器得到可播放地址，使用浏览器原生
音频控件及下载入口，不自动播放，不把工具专用 Workspace 或宿主机地址传给浏览器。
流式追加和回复结束复用已有 audio DOM，保留播放时间和音量；URL 真正改变时才重建。
语音附件由后端 ``useful.tts_synthesize`` 生成，识别由 ``useful.asr_transcribe`` 返回原文，
设置及模型选择仍属于后端，客户端不持有另一份配置。

解析与卡片数据更新分离
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

每个渲染器只投影其显式引用的 replacement 树及工具上下文徽标需要的隐式结果项。
其他卡片变化复用原投影；工具日志正文变化直接更新稳定组件上下文，不重新执行 Markdown
语法管线。只有原文、语法配置或执行状态分组的拓扑事实变化才重新解析；分组状态和权限仍实时更新。
复制正文按需解析并缓存到该次内容快照；执行窗口的辅助卡片不覆盖主消息的复制挂载点。

消息徽标条只在可见、溢出且未暂停时自动滚动，尺寸由 ResizeObserver 缓存，动画帧不逐次读取尺寸。
卡片自动置底通过同一帧队列先统一读取再写入，手动暂停在真正写入前再次检查。
工具命令高亮等待短暂停顿和空闲时段，隐藏或超长内容先保留可复制原文。
执行窗口工具长列表沿用 ``content-visibility`` 跳过屏幕外布局与绘制，保持原生媒体 DOM；
用户已经播放过媒体的工具卡完成时不自动折叠，手动折叠仍有效。

ESC 文档片段与占位边界
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``ESC_WRITE_REJECTED`` 可以表示模型未提供有效流 ID。此时即使 ``streamId`` 为空也显示
“文档写入未完成”，不伪造目标文档或提供无效跳转。拒绝片段通过 ``previewText`` 在同一组件中
显示为可折叠、可复制的原文数据，不再作为聊天的 Markdown 围栏，也不在原文中解析任何工具／卡片标记。
模型结束或切入工具只需完成组件数据更新；后续程序占位始终独立于该片段，不依赖反引号闭合。
原文可见不代表文档已经保存；成功上屏仍只显示状态组件，正文留在目标文档中。

Replacement
--------------------------------------------------------------------------------

现有消息使用 ``{{cardReplace ...}}`` 把正文占位与 Tool/Thinking/Widget 的前后端表示关联。它是
兼容现有持久消息的协议，后续可逐步迁移为 Structured Message Parts。

会话 Fork 使用只读历史快照。后端保留卡片类型和嵌套占位，并将 replacement 返回为
``{type, frontend, snapshot: true}``；不能把它降成字符串，否则只读标志会丢失。
``normalizeReplacementEntry`` 透传标志，``MarkdownRenderer`` 将它递归传给所有子卡。
工具调用、命令、日志和思考沿用现有展开/折叠展示；``executionWindowTool`` 在副本中仅作为
内部卡片的容器，不额外增加一个工具标题。历史工具默认独立折叠，失败或未结束的状态也不会继续动画。

执行、文档、后台任务和交互组件的快照只展示保存的描述与状态，不挂载原运行组件、订阅运行状态、
注册反馈、审批或恢复操作；执行状态采用紧凑行，空的 continuation 保持不可见。
快照不参与实时执行状态分组，复制文本及语音路径也不得触发原 ``FRONTEND_FEEDBACK``。
模型专用 backend 内容不会补入为空的 frontend，避免隐藏工具上下文出现在正文中。
HTML 快照沿用文本块显示源码，不挂载原始 HTML 按钮或事件处理器。

Widget
--------------------------------------------------------------------------------

``WidgetHost`` 根据 Widget 类型选择渲染器。Card Deck 支持滑动、撤回、分类和提交。Widget State
通过语义事件进入 Agent，而不是直接修改后端页面状态。

Execution Inline Trace 与窗口
--------------------------------------------------------------------------------

会话执行统一由 Execution Runtime 管理。普通 Agent 只要开始真实工具工作，
后端就通过 ``executionStatus`` replacement 在 Assistant 正文之间插入轻量执行状态。
同一阶段内多次工具活动会更新当前状态节点；阶段切换时旧节点变成完成态，并在正文后继续插入新的状态节点。
空的 ``executionStatus`` frontend replacement 表示该瞬时节点已被删除，前端必须返回空渲染，不能把它解释为
默认完成状态。Execution 的最终 ``执行完成`` 则由后端在 final Assistant response 结束后追加独立 terminal host，
不复用被清空的 continuation replacement。

点击状态节点打开会话级 ``ExecutionWindow``，其中展示 Execution Plan、模型/工具/完成门控的公开执行轨迹、
可恢复状态和用户补充记录。追加要求通过主聊天的 ChatBox 发送；窗口不展示隐藏思维链或原始 Provider Payload，
开发者级细节仍属于 Runtime Inspector。

自动化补充与平台来源
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

机器人事件在执行期间按 ``source=automation`` 投递为安全补充，正文和执行窗口都显示
同一份只读记录；不能再由“普通用户补充”的筛选条件隐藏。尚待安全边界消费、已接收和
模型回应后的状态均保留可见正文，不进入可编辑的用户待发送队列，也不提供撤回或重写按钮。

普通自动化输入的 ``extraInfo.messageOrigin`` 和执行补充的 ``displayOrigin`` 由后端从
已保存的事件构建。普通输入必须带 ``kind=automation``、``direction=inbound``，真正生成
的助手结果不带入站标记；用户配置为 ``assistant`` 角色的自动化输入仍可正确显示来源。
没有来源元数据的手动消息不通过正文关键词识别，也不会仅因助手结果具有自动化祖先就添加来源行。

两种位置复用通用 ``MessageOrigin``：平台、类型、昵称及备注读取标准 ``source`` 投影，
发言人读取 ``sender`` 投影。客户端不保存平台名称目录，也不根据平台原始编号猜联系人名称。
普通输入显示小号“自动触发”来源行与轻边线，执行补充保留“自动化补充／外部资料”状态。
点击来源按需展开备注、发言人备注和统一 ``botmsg_`` 消息引用；不展示令牌、临时回调地址、
平台原始消息 ID 或恢复字段。所有备注按普通文本渲染，不启用 HTML。

来源字段只作展示，不能授予工具权限、选择外发收件人或改变原模型消息角色。
来源行与消息正文作为独立兄弟组件更新；不会因消息完成或来源刷新重建既有音视频组件。

来源随补充队列、控制记录和执行活动快照持久保存，实时更新和刷新读取同一投影。
普通用户补充继续沿用原编辑／删除规则；智能体通信不会因此进入聊天正文。
设置中的机器人新建触发器和通用自动化编辑器均提供只读“回复来源”，由后端核验当前
账号所有权，失效或无权来源不回显其他账号信息。前端仍使用通用设置组件展示。

历史 ``executionMode`` replacement 仅被压缩成“旧执行记录”，旧 checklist 不再投影到主聊天 UI。
这是一层读取兼容，不允许新的 Turn 再进入 Execution Mode。

新增 Widget 的要求
--------------------------------------------------------------------------------

#. 定义稳定 Schema、版本和默认值；
#. 提供空状态、Loading、Error、只读态；
#. 键盘、触摸和语音都能操作；
#. 事件包含 Widget ID、Action 和 Value；
#. 不在模型文本中嵌入可执行 JS；
#. 增加快照/交互测试和模块文档。

.. important::

   “生成式 UI”不是让模型输出任意 HTML，而是让模型从受控组件协议中选择并填充数据。
