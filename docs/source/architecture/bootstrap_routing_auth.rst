启动、路由与认证
================================================================================

``main.jsx``
--------------------------------------------------------------------------------

Root 依次装配：

* ``ContextEvent``；
* Toast 与 Fatal Error Host；
* UniversalModalHost；
* ``WebSocketProvider``；
* React Router。

路由
--------------------------------------------------------------------------------

``createBrowserRouter`` 管理 Chat、Document 和 Login。``HistorySynchronizedRouter`` 监听旧代码中
仍存在的 ``history.pushState`` 路径，在 POP 时与 Router 状态校准，避免整页 reload。

``/chat/:conversationId?`` 共用一个 Dashboard 路由。消息地图是其 ``message-map`` 子路由，
以覆盖层呈现，底层 ChatPage、消息状态和实时订阅保持挂载。进入/退出地图及关闭设置不应
重建聊天运行时或取消当前 Conversation 的采集器；资源选择变化与组件挂载必须分开处理。
返回地图中的消息定位通过 Router 的 pathname/search 变化触发，不能仅依赖 ChatPage 首次挂载。

移动端顶部与导航
----------------

ChatHeader 的模型触发按钮靠左，短名称按内容自适应，手机端最大宽度 128px，较大屏幕为 320px，不扩展填满顶部；
窄屏可收缩以保留右侧按钮空间。文本容器使用 min-width: 0，名称 truncate；
右侧操作区 shrink-0，长模型名称或子 Agent 名称不能把按钮推到屏幕外。
手机端减小操作区间距，仍使用已有按钮和交互。
Sidebar 移除全局 touchstart/touchend 滑动开关；主导航通过显式按钮、遮罩与返回键关闭。
消息地图、卡片和浮窗自己的 Pointer/Touch 手势保持其领域职责。

后端广播启动与恢复
------------------

API 等待 Redis 广播订阅确认后完成启动，订阅断线后由统一传输组件重建。
前端继续使用现有二进制协议、作用域筛选与历史快照，不新增平行事件或任务状态机。
Pub/Sub 断线期间的消息没有补发保证，重连后的持久状态仍通过既有快照恢复。

认证初始化
--------------------------------------------------------------------------------

Dashboard 加载时先请求用户信息。401 由统一逻辑处理：

#. 只触发一次重定向；
#. 保存合法站内 redirect；
#. 不显示重复“加载失败”；
#. 登录后回到原路径；
#. 未认证时不加载 Notification 等受保护资源。

WebSocket 鉴权
--------------------------------------------------------------------------------

WebSocket 使用 Cookie。连接收到 4401 时停止自动重连并进入登录流程；普通网络断线才显示重试。

.. warning::

   redirect 必须限制为以 ``/`` 开头的站内路径，防止开放重定向。不要接受完整外部 URL。

StrictMode
--------------------------------------------------------------------------------

开发环境 React StrictMode 会执行 effect 挂载/清理再挂载。连接和认证代码必须幂等，不能因此创建
多个 WebSocket、重复 401 Toast 或重复事件监听器。
