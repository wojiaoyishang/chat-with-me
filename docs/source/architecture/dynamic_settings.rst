动态设置与后端连接边界
================================================================================

前端与后端设置
--------------------------------------------------------------------------------

设置窗口分别展示“前端设置”和“后端设置”。前端设置的目录与描述由客户端本机目录提供，
包括界面、后端连接和通知偏好；打开这些页面不要求后端提供设置目录或页面描述。
通知类型可以读取既有业务目录数据，页面本身仍由客户端定义。
目录的 ``categoryLabel`` 只作为标题，分组身份与保存键仍使用原 ``category`` 和 ``typeId``。

后端设置目录和 ``cwm.settings.v1`` 页面描述由当前后端提供，声明 ``scope=backend``。
本机页面声明 ``scope=client``。设置壳管理目录、加载、草稿、校验、保存与关闭，
不按后端页面 ID 导入 MCP、知识库、用户管理等专用组件。
``DynamicSettings`` 与 settings-runtime 共同渲染通用组件树，继续复用 shadcn/ui 和
共享 JSON 编辑器。新增普通后端设置只需后端组合已有组件，无需重新构建客户端。
本机界面能力与连接管理归客户端维护，不注册成后端设置页面。

页面包含 ``options``、``defaultOptions``、``saveMode`` 和保存操作。集合、表格、
矩阵、差异、字段组、弹窗与异步进度按通用交互分类。数据源、操作地址、条件、枚举和
字段联动均来自描述。禁止在渲染器中按业务字段名推断含义或为新功能增加专用页面映射。

页面正文从空白组件树开始渲染。页面级 ``title``、``description`` 和目录图标仅为导航
元数据，设置外壳不自动创建正文页头。标题由 ``options`` 中明确声明的 ``heading``
或资源工具栏展示；不能根据标题文字相同而自动隐藏组件。外壳仍统一处理导航、加载、
错误、草稿、滚动和保存，页面只编排内容。

视觉组件与排版
--------------------------------------------------------------------------------

前后端设置复用同一套通用视觉组件。``group`` 默认仅组织字段，``card`` 才显式添加
边框。资源集合采用紧凑工具栏和一层条目，避免集合卡片、条目卡片和属性底色面板嵌套；
明确指定 ``display=table`` 时使用表格。描述可提供纯视觉元数据，但不能借样式配置
加入领域逻辑。``profile-card`` 用有限引用组合紧凑资料与编辑字段，不单独注册账户或服务专用页面。

``group`` 可声明 ``variant=divided``：不增加卡片外框，标题下使用分隔线，组间留白
大于行间距，组内保持较浅的细线。界面偏好显式采用这一变体和单列设置行；通知仍是
紧凑列表。工具权限的矩阵分组使用独立浅边框、淡底标题和组间距，行内只保留细线，
从而区分组边界与条目分隔。展开箭头与正文共用收紧的左侧内距。

控件优先使用 shadcn/ui 原有 Button、Tabs、Separator、Accordion、RadioGroup 与 Card
的主题和布局。普通字段行保持紧凑，内容区之间才增加分组间距；不为每层添加图标底座、
阴影或大圆角。资源名称、数量和新增操作在同一个工具栏展示，说明只在必要的位置出现一次。

``profile-card`` 接收 ``id``、``title``、``subtitle``、``meta``、``actions``，以及
``options`` 或 ``children``。正文中的唯一 ``slot=avatar`` 图片上传字段放到头部，
复用该字段的上传和预览，避免重复显示头像。正文可按组件树组合字段，头部动作可容纳
退出登录；账户页面将昵称编辑与保存动作放在独立的“个人资料”分组。组件不持有账户
接口或固定业务字段，头像与昵称仍按根表单字段一起保存。

资源组件可声明 ``recordView:{type:"connection-card",state:{field,labels,tones}}``，
连接条目复用原有标题、说明、图标、属性列和动作，由同一资源组件管理请求及编辑状态。
``columnsCount=2`` 按实际内容容器宽度最多显示两列，窄容器自动回到一列；
``connection-card`` 也可作为独立的受限引用展示组件，不另建连接业务页面。

``form-layout`` 使用 ``layout=stacked|compact``、可选 ``columns=1|2`` 和
``options`` 或 ``children`` 组合字段。它与 ``profile-card`` 都是透明表单容器，
不添加值路径，继续参与默认值、校验、保存和错误聚焦。资源编辑器与动态对话框默认
采用 stacked 排布；页面宽度自适应，具体字段可由显式布局约束，避免在宽弹窗中横跨空白。

资源的 ``editor.dialog`` 和后端返回的动态对话框根级 ``dialog`` 可指定尺寸，例如
``{"width":640,"maxHeight":800}``。二者接受像素数值；宽度限制在 320 至 1600，
最大高度限制在 240 至 1600，同时受当前视口内边距约束。非数值使用默认值，不接受
任意 CSS。高度随内容增长，超过限制时仅正文滚动。ComfyUI 工作流、服务连接、MCP
等由各自后端描述选择合适宽度，前端不按页面 ID 推断尺寸。
客户端连接资料编辑器使用 480 像素的自然宽度，同样受视口边界限制。

通知偏好采用单列紧凑列表：分组小标题、左侧名称与说明、右侧对齐开关，支持搜索，
不套卡片或使用双列。前端本机标签复用原有图标，所需静态资源随客户端发布；后端标签
使用当前目录给出的 ``preview`` 图标。

通用 ``tabs`` 组件按 ``tabs[].options`` 组织页面，标签不增加表单值路径。
ComfyUI 主页面区分工作流模板与服务连接，编辑器区分基础信息与工作流参数。
切换只改变可见内容，保留各页的值和编辑草稿；隐藏页仍参加校验，失败时应显示对应页。
标签支持左右方向键、Home 与 End；只读表单仍可切换。嵌套标签和隐藏 JSON 草稿的错误
同样需要展开相关标签并聚焦，不能只检查当前可见页。

内容区域按实际容器宽度适配列数，窄屏导航保留可读标签。长参数和资源标识不得撑出窗口，
编辑对话框的正文独立滚动，操作区保持可达。明暗主题、加载、空数据、失败及只读状态
继续使用公共 UI 原语。

嵌套窗口与下拉菜单复用 WindowLayer。明确标记 ``data-window-popover`` 的自有弹层
继承窗口身份与层级；其交互不关闭父窗口，普通外部点击仍保持原行为。共享 JSON 编辑器
的纯 DOM 下拉也遵循此约定，源码在后端 packages/json-config-editor，构建后同步版本化
客户端包，不在设置页加局部超大 z-index 补丁。

共享确认框独立管理打开状态和请求文案。关闭时保留该次标题、说明、按钮及危险样式，
直到 Radix 退出动画移除弹层，避免先清空文案产生空白闪框；不通过延迟计时器补救。
每次请求具有独立身份，过期关闭回调不能取消新请求，替换请求和卸载均结束对应的等待。

动作与状态
--------------------------------------------------------------------------------

动作使用有限 ``$ref`` 引用 ``form``、``item``、``response`` 或 ``client``。
接口参数经过编码，只接受选定后端的 API 路径；数据转换与条件使用明确支持的操作，
不执行后端提供的代码。动作效果统一处理刷新、表单更新、弹窗、页面跳转和反馈。
后台操作继续查询既有任务或操作状态，进度查询不能重复提交业务操作。
目录、页面、资源、详情、文件读取和动作请求统一使用顶部浮动吐司。按钮保留原图标、
宽度和禁用状态，不再追加行内进度块或加载占位。动作以稳定身份更新同一条吐司，
``pendingText`` 提供初始文案，进入轮询后显示阶段、百分比及“查看详情”；读取暂停时
提供“继续读取进度”，只恢复状态查询。组件卸载时清理其提示，不取消服务端后台任务。
成功反馈由后端的 ``effects`` 中 ``toast`` 或 ``successText`` 明确声明，前者优先，
避免同一次成功重复提示；不根据按钮名称推断含义。
``async-operation`` 可声明稳定身份及状态恢复接口；提交结果不确定时只读取核对，
403 不触发恢复绕过。``open-dialog.value`` 可引用后端返回的完整描述，弹窗内部有独立
表单状态并使用同一动作执行器。矩阵批量联动和上传保存值／预览值分离也由描述声明。

表单草稿与服务器快照分开。保存期间的新编辑不得被较早响应覆盖，版本冲突不丢失
用户输入。资源编辑器只按描述组装可写字段；凭据不通过列表回显，也不保存到普通草稿。
未知组件显示能力错误，不把它自动当作 JSON 编辑器。

加载与窗口缓存
--------------------------------------------------------------------------------

加载完成后内容仅以透明度淡入，保留原排版；遵循系统的减少动画偏好。刷新资源时保留
已显示的条目，不插入进度行。页面失败时使用覆盖内容区的半透明背景和淡入错误面板，
保留重新加载入口；后端引导失败使用同样的全屏恢复层，允许打开本机连接管理。
吐司 Host 位于后端引导组件之外，首次连接和连接恢复阶段也可反馈进度。

前端“界面／设置窗口”提供默认开启的 ``CacheSettingsPages``。缓存是当前设置窗口的
私有内存，只保存成功加载的目录、页面描述、服务端表单初值及资源集合。切换页面可复用
这些快照，关闭窗口、切换后端或账号、关闭缓存开关都会清空；不写入 localStorage 或
IndexedDB，也不保存用户输入的未提交密码或令牌。草稿退出确认与原来的权限校验继续生效。

页面描述根级及 ``resource`` 节点可以声明 ``cache:false`` 排除对应快照。资源缓存键
包含解析后的数据源、查询参数及父记录身份，不能复用其他参数或父记录的结果。失败响应
不进入缓存。显式刷新跳过缓存，保存更新服务端快照或使页面失效；描述声明的 ``events``
同时使相关快照失效，即使页面已隐藏也不会在下次打开时恢复过期数据。缓存开关只控制
读取复用，不改变请求权限、服务端持久状态或后台操作生命周期。

目录名称与分组矩阵
--------------------------------------------------------------------------------

聊天工具菜单、会话权限和默认工具设置使用后端目录给出的友好名称，不把工具集标识或
任意目录文案当成本地翻译键。工具集与工具没有显示名称时才使用其原始名称。原始标识、
``ToolRef`` 和权限键保持稳定，显示名称及分组变化不改变工具身份或授权。
界面自身的按钮、提示和权限选项继续使用客户端本地翻译。

通用 ``matrix`` 通过 ``groups:[{id,label,description?}]`` 声明分组；扁平 ``rows``
使用 ``row.group`` 引用分组 ``id``，``row.id`` 继续作为保存键。默认展开首组，其他组
可以折叠；搜索时展示并展开命中的组，清空后恢复原折叠状态。没有分组声明时继续支持
普通矩阵并保持行顺序。

每行互斥列使用单选语义，UI 选项映射回列的原始值类型。全局批量操作处理全部可修改行，
不以当前搜索结果或折叠状态为作用范围；已有的禁用、允许值、锁定策略和危险确认继续生效。分组只影响展示，不为
默认工具增加一套权限继承，保存仍由原服务端接口处理。

``groups[].bulkActions`` 可以给分组增加“全部允许／全部询问／全部拒绝”，动作沿用
全局按钮的 ``label``、``value`` 和 ``confirm``。组内全部允许仍显示危险确认。
组操作只遍历该组全部原始行，搜索和折叠不缩小范围；锁定与允许值约束继续生效。
组操作不执行 ``set``，不改变其他组或全局 ``fallbackMode``。全局 ``bulkActions.set``
仍可执行描述中明确声明的整页字段联动。

全局和组内批量按钮的图标、颜色由动作的 ``icon``、``tone`` 声明；默认工具使用
``shield-check/success``、``circle-help/warning``、``shield-x/danger`` 区分允许、
询问与拒绝。渲染器只接受受控的图标与主题色，不按标签文字推断含义。展示元数据不改变
权限，危险确认仍由原 ``confirm.danger`` 控制。
批量按钮采用 ``variant=ghost``，保留图标和完整文字。受控 tone 为 success、warning、
danger、info，显式 tone 优先于危险确认的默认颜色，允许按钮可显示绿色并继续要求确认。
未知图标不显示，未知 tone 使用受控默认策略，不接受任意 CSS。网络动作忙碌时禁用按钮，
加载进度由浮动吐司展示。

扩展组件
--------------------------------------------------------------------------------

``registerSettingsComponent`` 注册的是可复用控件类型。``node-graph`` 接收已解析的
图值，支持节点搜索、拖动缩放、子图导航、参数绑定和产物选择。字段的目标、类型和默认
策略由后端提供；参数面板仍调用通用字段渲染器，不引用第三方业务专用设置页面。
图布局算法在通用模型中共享，避免旧页面与新组件出现两份布局逻辑。

运行观测渲染器以带摘要的版本化产物随客户端发布。普通 ``--check`` 校验本仓库产物，
无需邻接的后端源码目录；维护者更新时通过 ``--source`` 明确提供唯一源码位置。
通用组件的构建依赖与运行时选定的后端地址互相独立。

后端选择与隔离
--------------------------------------------------------------------------------

客户端将后端配置和当前选择保存在 localStorage，直到用户在客户端明确切换。刷新继续
使用同一选择，断线或登录失效不能自动切换。初始同源部署仍可使用 ``/api`` 入口。
登录凭证按后端隔离在 sessionStorage，密码不进入连接配置。

HTTP、控制 WebSocket、实时语音、资源 URL 和页面消息使用同一个连接上下文。
请求带有连接代次，旧连接的响应和事件不能更新新后端。离线待发队列属于原连接，禁止
随新连接重新发送。手动切换检查未同步文档并保留草稿，再重新加载客户端以清理旧单例；
切换本身不取消后端已经接受的任务。

业务状态按后端与用户隔离，包括任务、执行模式、通知、消息配置目录、文档卡片定义、
聊天草稿和文档离线数据；设备外观偏好仍共用。``cwm://`` 引用由所属连接解析。
后端托管页面通过明确来源与 frame 身份校验通信，跨源读取使用受限凭证。
管理页的业务请求由宿主桥代理；长期登录令牌不进入 frame，凭据接口及其编码变体均禁止
从桥访问。设备偏好读写拒绝连接配置及后端数据保留命名空间，未知存储作用域明确报错。

测试要求
--------------------------------------------------------------------------------

运行组件模型、真实组件交互和连接隔离测试；验证前端页面独立于后端设置能力，后端目录
不重复提供本机页面，且两类页面共用渲染原语。两个隔离后端使用相同的用户、会话和任务
ID，确认切换后无状态混用。
覆盖保存期间继续编辑、版本冲突、条件字段、秘密保留与删除、失败后重试、取消订阅、
后台进度、节点共享参数和子图导航。构建通过后同步两端 RST 和静态 API。
