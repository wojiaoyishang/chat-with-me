HTTP、认证与 401
================================================================================

请求规则
--------------------------------------------------------------------------------

* 通用设置的地址与动作来自当前后端描述，其余既有资源接口通过同一连接对象解析；
* 显式连接使用按后端隔离的 Bearer 会话，同源初始部署可交换既有 Cookie 会话；
* AbortSignal 取消卸载请求；
* 业务错误显示领域提示；
* 401 交给统一认证流程。

401 去重
--------------------------------------------------------------------------------

并发请求可能同时返回 401。重定向逻辑必须有全局锁/状态，只执行一次并保存站内 redirect。Dashboard
不应同时弹出多条“Unauthorized”。

每个请求同时携带连接配置与代次。切换后端后旧请求的 401、成功与失败都按取消处理，
不得清除新后端凭据或触发它的登录跳转。登录凭证与用户身份放在按后端隔离的 sessionStorage，
localStorage 只持久化连接选择与非机密配置。

资源加载
--------------------------------------------------------------------------------

认证未完成前，不加载 NotificationHost、Conversation 列表和设置。认证成功再挂载受保护 Feature。

错误信息
--------------------------------------------------------------------------------

后端统一响应可能包含 code/msg/data。前端不要假设网络错误一定有 ``response.data``，要兼容断网、
取消和非 JSON 响应。

.. warning::

   退出登录后应关闭/停止 WebSocket 重连，避免旧连接不断收到 4401。
