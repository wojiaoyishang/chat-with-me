# Chat With Me 代码规范与 AI 开发约定

生效日期：2026-10-03。适用于前端与后端，以及后续 AI 维护。本文结合项目现有架构与 Clean Code 原则制定；“必须”是约束，“优先”允许根据实际职责作出有理由的选择。

## 1. 开发前的阅读与边界

- 修改前阅读本文件、同目录的交接文档、对应领域 README 和相关开发手册；通过实际代码核实文档。
- 检查工作区已有修改，保留用户和其他维护者的工作，不擅自覆盖、回退。
- 搜索已有组件、Hook、Store、工具函数、服务和接口，阅读调用方、状态、错误处理和副作用；不能仅凭名字判定可复用。
- 跨项目修改必须核对双方的接口、事件和状态契约。
- 当前用户明确要求优先；若需要偏离规范，在交接记录中说明原因、影响和后续安排。
- 新增和本次实际修改的代码遵循规范，不借任务之名重写无关旧代码。

## 2. 复用与新增模块

复用顺序：直接使用现有实现 → 组合现有实现 → 扩展已有实现 → 新增模块。

- 相同职责必须优先复用，不复制后改名。界面差异优先用属性、变体或组合表达。
- 常规新功能放入已有业务领域。只有新功能明确需要独立模块架构时，才引入新模块，并说明职责、边界、复用部分和新增理由。
- 不新增重复的 API 客户端、事件总线、任务执行循环、审批系统、资源访问协议或状态权威。
- 不为尚未出现的需求预建通用框架。若抽象需要大量模式开关和特殊分支，应重新评估职责，而非强行合并。

## 3. 前端 UI 与组件

- UI 标准以 shadcn/ui 为基础，优先复用项目已有封装及业务组件，保持视觉和行为统一。
- Button、Input、Dialog、菜单和选择器等基础控件，先查找 `src/components/ui/`；业务交互先查对应 Feature、Hook 和 Store；消息、附件、卡片、浮窗和确认交互先查已有实现。
- 缺失控件可以通过 npm 安装所需依赖，并使用 shadcn CLI 添加组件。先核对项目的 `components.json`、React/Tailwind 版本及已有组件；新增应使用兼容配置，不覆盖已有定制。
- 依赖管理使用 npm，安装后同步提交 `package.json` 与 `package-lock.json` 的必要变化；不为单一小需求引入功能重叠的大型组件库，不顺带升级无关依赖。
- shadcn/ui 组件源码由项目维护。业务规则放在 Feature 中，不塞进公共 UI 原语；HTML 用于语义、布局和基础结构，避免重复手写已有标准控件。
- 颜色使用语义主题变量，遵循已有变体、图标、间距、圆角、字体和交互；兼容明暗主题，不靠页面级覆盖形成独立风格。
- 覆盖加载、空数据、失败、禁用和只读状态；支持键盘、焦点、可访问名称及移动端。
- 旧组件在涉及本次修改时逐步统一，不进行无关的全量替换。

## 4. 可读性与 Clean Code

- 名称表达业务含义，沿用项目词汇；布尔值采用 is/has/can/should 等明确语义。时间、重试次数、容量等常量有名称和单位。
- 函数承担单一明确职责，避免同时混合请求、持久化、协议处理和 UI 更新；保持同一抽象层次。
- 多个有关联的参数使用具名对象或上下文，避免难理解的位置布尔参数。
- 使用提前返回减少嵌套；区分计算与副作用，显式表达依赖和资源所有权。
- 注释说明原因、约束和非显然的取舍，不复述代码；移除失效注释和无用的注释代码。
- 不机械限制函数行数，不为了拆分而拆分；沿用局部格式，不进行无关格式化或 JS/TS 迁移。

## 5. 前端架构与状态

- Page 负责页面装配，Feature 承载业务逻辑，公共组件承载可复用表现。
- HTTP 复用统一 apiClient，实时事件复用既有协议、传输与事件 Store。
- 局部状态放组件或 Hook，共享业务状态放相应领域 Store；后端持久状态是权威来源。
- Event Store 不承担持久业务数据库职责。快照合并不得覆盖更晚的实时状态。
- 订阅、路由和展示组件不得各自实现第二套生成或任务生命周期。

## 6. 后端分层与依赖

- 新业务放入 `application/` 的相应领域；根目录入口及 application 根层保持启动、装配与配置职责。
- Router 负责认证上下文、输入校验、调用业务能力和响应转换；可复用业务规则在领域服务中实现。
- Worker 负责长任务入口和运行环境集成，核心业务能力尽量留在所属领域，避免 HTTP 和 Worker 各复制一份。
- core 保持轻量，适配器封装外部传输和存储；Models 不发送 WebSocket 事件。
- 通过明确参数、上下文或既有装配机制提供依赖，避免隐式全局运行状态和导入时启动连接、任务或事件循环。
- 异步路径不得执行长时间阻塞操作；使用项目已有异步适配或任务机制，不随意新建线程、事件循环或轮询框架。
- 复用既有配置与客户端，保持连接池、会话及客户端生命周期可控。

## 7. 后端接口、权限与数据

- 使用项目既有请求模型、响应封装和错误语义；入口校验类型、范围、必填项及资源关联，业务层维护业务不变量。
- 资源读取、修改和工具执行必须通过既有身份、所有权与授权机制，不能仅凭前端传入的 ID 信任访问。
- 数据访问沿用 SQLAlchemy 及现有仓储/领域模式；使用参数绑定，不拼接用户输入形成查询。
- 事务边界明确，相关写入保持一致性；失败回滚，及时释放会话，不跨长时间网络等待持有无必要的事务。
- 修改数据结构要提供与项目机制兼容的迁移或升级步骤，并说明既有数据如何处理；不得把删库重建作为正常升级方案。
- 对外状态变化及事件发布沿用现有一致性机制，避免数据库写入失败却通知成功；重试与重复请求必须考虑幂等。
- 日志包含必要的 conversation/run/trace 等标识；不得记录令牌、密码或无必要的完整用户内容。
- 文件及 Workspace 访问使用既有授权、路径校验和资源服务，遵循 `cwm://workspace/@<workspaceId>/<path>` 契约；不绕开隔离直接接受任意本地路径。

## 8. 后端执行、模型与工具

- execution 是持久执行的统一权威，Task Mode 是其投影；不建立第二套完成、取消、恢复或审批状态机。
- 明确区分 conversation、message、turn、run、stream、trace 标识，不能相互代用。
- 保持 Protocol v1、MsgPack 封装及现有 RPC 关联方式，不新增旧式 JSON 协议兼容分支。
- Prompt 使用集中模板环境，第一方模板遵循既有 StrictUndefined 约束；用户、工具和记忆内容按字面数据处理，不当作模板执行。
- 工具暴露沿用每次请求冻结的 ToolExposureSnapshot，使提示、Schema、发现、校验和准入一致；执行时仍校验实时注册与授权。
- 模型接入沿用现有适配层，保持 Completions/Responses 等协议边界和思考内容处理，不混用线格式。
- 普通生成内容即时流式交付；仅在既有强制完成语义确实要求时缓冲。任务完成仍经过既有完成门控。
- 外部调用设置适当超时，取消和异常路径释放资源；重试有界，并避免重复工具副作用、导出和通知。

## 9. 异步、流式与资源生命周期

- 创建订阅、连接、定时器或任务的代码明确负责清理；清理必须对应自己拥有的资源。
- 打开地图、设置或辅助浮窗，以及普通重新渲染，不得中断当前运行；真正切换会话时才按既有语义取消离开的资源。
- 迟到事件不得写入已切换的会话或运行；订阅正确处理卸载、重新注册和 React StrictMode。
- 流式事件保持必要的 FIFO 顺序，不因监听器替换丢失已排队数据，不阻塞到整轮结束才展示。
- Promise 和后台任务必须有明确失败处理；避免无人消费的异常和无限重试。
- 快照、重连及历史补偿与实时更新协调，不能使状态回退。

## 10. 根因修复、错误与验证

- 多组件出现相似故障时先检查共用链路，建立可复现条件，再修复负责该行为的层。
- 不用刷新页面、吞掉异常、禁用交互、丢帧或任意等待来掩盖问题。已有临时补救在证据充分时移除；合理的超时、节流、重连和快照机制保留并解释。
- 错误应明确传播、转换为既有错误结果或有理由地降级，同时恢复可继续使用的状态。
- 验证与风险匹配：涉及状态、协议、权限、并发、持久化或生命周期的行为提供有意义的回归检查，尽可能证明旧实现失败、新实现通过。
- 测试验证行为而非复制实现；小型可逆的样式或文档调整不强制新增测试。
- 运行适用的前端构建/检查，以及后端语法、架构和行为检查。界面变化在条件允许时检查真实交互，构建通过不等于交互正确。
- 检查无法完成时说明原因、既有失败和新增失败；不通过关闭规则、删除测试或扩大忽略范围掩盖问题。

## 11. 交付与文档维护

- 说明修改内容、原因、复用位置或新增模块理由、验证结果，以及必要的重启、迁移、未验证事项和风险。
- 每次完成修改更新 `docs/交接文档.md`；架构、协议或开发流程变化时同步对应手册。
- 跨项目修改分别记录各自影响，确保接口和生命周期描述一致。
- AI 开始后续维护时先阅读本规范和交接文档。本文是项目约定，其实际遵循依赖维护者主动阅读。

## 前端反馈工具的维护约束

复用 call_tool.delivery、既有审批与 managed ToolCall。前端只提交 msgid/toolid，执行参数从服务端登记的 intent 读取；不要新增接受任意工具名、参数或代码的客户端执行入口。默认机器人 delivery 显式 once=true，显式 delivery 缺省 once 允许重复，限制由后端统一执行。播放触发必须绑定真实音频开始，刷新、暂停与中断不能补执行历史工具；具体协议见 [前端反馈调用模式](前端反馈调用模式.md)。
