# 协作文档

## 范式与边界

文档是持久资源，`documentId` 与成员关系复用已有 Document。浏览器关闭仅离开编辑，不取消后端任务。LLM 的修改以 `kind=ai`、用户授权、conversationId/runId 记录；客户端不能自行指定作者。Collabora 保留为 Office 编辑适配器，Markdown 使用原生源码／实时预览。

移除旧 `/document/redirect/{id}`、表单创建／修改、前端文档操作 RPC 与 onlineDocument 工具集，不提供旧接口兼容。已有 Office 文档 ID、成员关系及文件保留，重新通过公共 editor API 打开；需重新启用 documents 工具权限。Office 第一轮支持读取、追加文字和唯一原文替换，不开放任意 UNO 命令或 Python 脚本。

## 公共 API

- GET/POST `/document`：列出／创建，创建 JSON 为 title/format/content，format 为 markdown 或 docx。
- GET/PATCH/DELETE `/document/{id}`：元数据及文本读取、改名、删除。
- GET `/document/{id}/editor`：按格式返回 editor，Office 返回已鉴权 WOPI URL。
- GET `/document/{id}/history`：最近 100 个 Git 保存版本的时间、说明和作者。
- POST `/document/{id}/export`：导出 artifact URL。

`document.sync` 沿现有 MsgPack 控制通道发送 document_id 和 Base64 CRDT update/stateVector；响应为 state/stateVector/revision/participants。服务端按文档成员鉴权，以当前登录身份登记作者。已有数据库的 Document 行锁串行化同一文档的多个进程写入；每次从持久状态建立私有副本，合并成功后事务保存 DocumentState 与 DocumentRevision，再广播 `document.sync.changed`。重复 CRDT 提交不重复增加版本。广播失败不谎报未持久化，周期同步补齐状态。

Redis 仅广播和在线状态，在线记录 45 秒失效，不能作为正文权威。客户端每 40ms 合并输入发送，10 秒只做状态校准；通过状态向量只交换缺失增量。IndexedDB 按用户／文档隔离，连接前校验访问权。离线编辑保存在本机，后端确认持久化后才显示“已同步”；未同步关闭浏览器会提示，重开后重发幂等增量。

## 工具规范

公共入口 documents.document_create/document_get/document_read/document_export。先 get 能力，再 read 正文与 revision；Markdown 用 document_edit_text，Office 用 document_edit_office。浏览器是否打开不影响工具执行。

文本 operations 支持 insert/replace/delete，start/end 为 Unicode 字符索引，多个操作的位置基于前一操作结果；replace/delete 必须 expected 原文，一次事务至多 100 个操作。revision 必须匹配读取版本，过期返回 DOCUMENT_CONFLICT，模型应重读再决定；不自动覆盖用户修改。后端转换 pycrdt 的 UTF-8 索引，中文和 emoji 已做 Yjs 跨语言回归。工具返回业务版本，不向 LLM 返回 CRDT 编码。

Office revision 为正文 SHA-256，operations 首版为 append_text(text) 和 replace_text(expected,text)。服务端 Collabora macro 检查版本及唯一替换目标，通过范围编辑保留格式并合并为一个撤销事务；成功须等待保存确认。其在线协作仍由 Collabora 承担，不把 Office 二进制强行转成 Markdown CRDT。

## 部署

1. 安装后端 requirements.txt（pycrdt==0.14.8、filelock==3.29.0），运行环境须提供 Git 可执行文件。
2. 使用既有配置执行 `python -m application.documents.migrate`，只新增 document_states/document_revisions；首次建库的 init.database.py 也会创建。
3. 将新增 docker/collabora/scripts/ChatWithMe/documents.py 同步到 Collabora 的共享脚本目录，重启对应服务以加载；保留已有 WOPI 配置。
4. 前端 npm install 后构建，启动新分支的 API 和 Worker。
5. 会话重新启用 documents 工具集；旧 onlineDocument 权限不做自动映射。

首轮限制：Markdown 正文最多 1MB，CRDT 状态和单次更新最多 2MB。当前存储和版本机制见下文；已提供 Git 历史恢复界面和彩色光标共享，LaTeX 编辑器尚未实现。合并到正式目录后已安装新增依赖并执行新增表迁移；未修改已有文档正文。Office 真实服务联调需部署新 macro 后完成。

## 2026-10-05 实时在线状态与共享选区

在线状态完全由现有控制 WebSocket 驱动，HTTP 只用于首次授权与文档元数据读取。document.sync 加入协作时携带 clientId 和当前 cursor；document.presence.update 单独传递 Yjs 相对位置 anchor/head，不访问数据库、不写修订。document.presence.changed 广播成员与选区快照，附递增 presenceRevision，前端拒绝旧快照，避免乱序复活旧光标。服务端根据登录用户填写昵称与颜色，不接受客户端身份或颜色。

application/documents/presence.py 管理连接绑定与 Redis 短期在线投影；router/websocket/documents.py 管理事件及生命周期。正常离开、页面 pagehide、WebSocket 断开都立即撤销连接对应成员并通过 WS 广播；异常链路仍以底层 WebSocket 心跳判定断开，45 秒的 seen 检查仅作为服务异常时的过期保护。一个用户的多个页面按一人在线计数，页面仍保留独立光标；clientId 校验避免旧页面的延迟选区/离开事件破坏新会话。每个物理连接串行处理协作生命周期，关闭后的未开始请求不会重新注册成员。

前端 presence.js 是独立 Awareness provider，使用 y-protocols 和 CodeMirror 已有 yCollab 实现远端彩色光标及多行选区；相对位置随并发正文编辑移动。光标/选区变化在 40ms 内合并送出，掉线立即清除远端光标与在线列表，重连由 WS 重新加入。光标更新直接驱动 CodeMirror，只有成员身份变化才更新页头，避免重复渲染 Markdown 预览。

界面移除修订编号，使用已有 Button/Avatar/Tooltip 的紧凑工具栏，提供编辑、双栏、预览切换及成员颜色提示。后端版本校验继续保护 AI 编辑冲突。新增真实 Redis 上的 WS 事件/断开/刷新晚到事件回归，以及真实 Awareness 的相对选区、成员去重、乱序与本地 transport.disconnected 事件回归。桌面和手机预览页检查通过。

断线后忽略迟到的成员广播；正文同步按连接代次丢弃旧连接 ACK，重连不用等待旧请求超时。前端构建验证使用临时 UV_THREADPOOL_SIZE=1 完成；默认线程池的 gzip 体积统计阶段在本机出现 Node 原生异常，未修改项目构建配置或产物选项。


## 2026-10-05 独立目录、Git 版本与 Markdown 工具栏

每个新 Markdown 文档使用 `Config.DOCUMENT_PATH/<documentId>/`，默认配置为后端项目的 `documents/`。目录只有 `main.md`、`assets/` 与私有 `.git/`；没有 `.internal`。默认正文从 UTF-8 `main.md` 读取，Markdown 的 `assets/...` 相对资源由鉴权资源接口解析。数据库保存文档元数据/成员权限、Yjs 协作状态、revision 和 `extra_info` 中的写盘状态；Git 保存正文和附件的历史。旧 Markdown 记录不迁移、不兼容，在列表隐藏并拒绝打开，已有数据不自动删除；Office 文档继续使用 Collabora。

`application/documents/storage.py` 只执行预定义 Git 参数，文档标识限制为 UUID，不执行 shell、hooks 或远程推送；版本接口只接受属于本仓库历史的完整 commit SHA。只暂存 `main.md` 和 `assets/`。`.git/cwm-write.lock` 提供跨进程文件锁，同时复查成员权限并锁数据库记录。API 与 Worker 必须挂载同一个 documents 目录；不可直接在文件系统修改正文，摘要不符会报冲突，不会静默覆盖。备份需要同时备份数据库与 documents 目录。

实时输入仍通过 WS/CRDT 同步：数据库先提交协作状态和持久写盘意图，再原子替换 main.md，成功后清除意图。写盘失败可在重试或重新打开时完成，浏览器关闭不取消 AI 编辑。Git 与实时落盘解耦：手动 Ctrl+S/⌘S 或保存按钮先等待当前输入的 WS 确认，再保存 Git 版本；内容未变化不产生空版本。输入停止约 5 秒后自动保存，连续输入最长约 60 秒形成版本；AI 编辑每次立即保存。自动计时任务是进程内调度，重启后的读取/写入也检查持久脏标记并补存版本。文件写入完成但 Git 失败时保留待保存状态以便恢复。

新增接口：

- POST `/document/{id}/save`：`{revision, note?}`，返回 commit/created；并发版本不符返回 409。
- GET `/document/{id}/history`：最近 100 个 Git 版本，字段 commit/createdAt/note/actor/revision/kind。
- GET `/document/{id}/history/{commit}`：历史正文及相对当前正文的差异。
- POST `/document/{id}/restore`：`{revision, commit}`。先保存当前修改，再把历史正文通过当前 CRDT 文本事务恢复，恢复附件后产生新 commit，通过 WS 广播；不执行 reset，不抹除已有历史。
- GET `/document/{id}/assets/{path}`：复用成员鉴权，拒绝越界、隐藏路径及符号链接。常用位图内联，其余文件下载；资源总量限制 100MB。当前只提供资源读取与历史恢复基础，文件上传/管理器留给后续功能。
- WS `document.version.changed`：保存/恢复完成后通知版本列表；在线与离线状态仍全部通过 WS。

前端沿用 CodeMirror + yCollab + 现有 MarkdownRenderer。工具栏复用 shadcn Button/Tooltip/Popover/Input/Dialog，包含撤销、重做、标题、粗体、斜体、删除线、列表、引用、代码块、链接/图片插入、保存、版本历史。保持左源码/右实时预览，手机默认编辑并可切换预览，格式工具横向滚动，保存和历史固定可见。窗口级快捷键阻止浏览器保存网页，并兼容 macOS ⌘S。历史界面支持正文查看、差异和确认恢复；未使用额外编辑器或另一套协作协议。

验证：隔离 SQLite + 临时 Git 仓库覆盖创建、手动/AI 版本、正文与附件恢复、权限/路径校验、版本冲突、写盘故障恢复、外部修改冲突及跨服务并发；真实前端 Hook 覆盖尚未同步时立即保存、请求中追加输入、断线重连；工具栏覆盖 Unicode 与重复格式切换。浏览器预览验证 Ctrl+S 保存成功、历史显示和手机布局。临时测试不操作真实用户文档。

## 2026-10-05 文档句柄与持久 AI 协作者

本节替代早期工具按 document_id 直接读写的调用规范，不保留旧参数兼容。

1. `document_create(title, format, content)` 创建持久文档并返回 documentId；创建不等于加入协作。
2. `document_open(document_id=None)` 打开并加入 AI 协作者，返回 `resource_id`、文档格式/能力与时限。省略 ID 只使用本次请求携带的当前界面文档；没有当前文档必须显式提供 ID，不回退到会话曾保存的旧 ID。
3. `document_get(resource_id)` 查看文档信息；`document_read(resource_id, start=0, end=-1)` 读取正文和 revision。
4. `document_edit_text(resource_id, revision, operations)` 编辑 Markdown；`document_edit_office(resource_id, revision, operations)` 编辑 Office；`document_export(resource_id)` 导出。文档 ID 不能代替句柄。
5. `document_close(resource_id)` 释放连接并退出，不删除文档、不撤销已保存编辑。默认空闲 600 秒、最长持有 7200 秒，由共享资源框架清理；过期/Worker 死亡后返回句柄不可用，需再次 open。

Markdown 操作只接受 kind/start/end/expected/text，kind 为 insert/replace/delete；不接受 type=append 等别名。追加先读取完整正文，以返回 end 为 insert 的 start；replace/delete 必须匹配 expected 原文。复杂操作通过结构化 DocumentTextOperation 暴露，厂商 Schema 明确列出字段、类型、必填项及允许值；反射 call_tool 的说明提供相同示例。未知字段错误指出 operations 下标和字段名，不猜测修复参数。

例如当前界面有文档时：

```json
{"toolset":"documents","tool":"document_open","arguments":{}}
```

读取句柄：

```json
{"toolset":"documents","tool":"document_read","arguments":{"resource_id":"document-session-<返回的资源ID>"}}
```

空文档的第一次插入（revision 使用刚读取的值）：

```json
{"toolset":"documents","tool":"document_edit_text","arguments":{"resource_id":"document-session-<返回的资源ID>","revision":0,"operations":[{"kind":"insert","start":0,"text":"测试写入内容"}]}}
```

`application/documents/resource.py` 声明 document_session，共享现有 ResourceRuntime 注册/单一 owner/跨 Worker Redis RPC/身份校验/idle/hard TTL。真实 aiohttp WebSocket 连接存于 owner Worker 的运行时循环，任务结束和浏览器关闭不销毁资源；后续任务即使迁移 Worker 也由 RPC 路由到原 owner。连接不可恢复时明确报错，不自动重放修改。

Worker 通过 `Config.DOCUMENT_COLLABORATION_URL` 连接 `/{documentId}/collaborate`。默认直连本机 API 为 `ws://127.0.0.1:8000/document`；API 端口不同、反向代理或集群部署需设置可达的内部地址，并支持 WS 升级。连接票据存 Redis，仅 30 秒有效且单次消费，绑定用户/会话/文档/资源；票据不交给 LLM，也不返回前端。API 每次读写重新校验成员权限，再调用公共 DocumentService；正文、CRDT、文件和 Git 仍由原服务处理。

API 连接生命周期通过已有 DocumentPresence 广播 AI 进入/退出。独立 15 秒在线心跳不延长资源空闲期限。前端在线列表把 AI 句柄与授权用户区分，仍将同一真人的多个页面合并。Office 打开时载入 Collabora 并维持参与者连接，读取/编辑共用该 socket，关闭句柄时一并关闭。

回归包含真实本地 WS、隔离 SQLite/临时 Git 和两个 ResourceRuntime：打开加入、跨 Worker 读写、未知参数、跨用户禁止、关闭退出、超时关闭、缺省当前文档与失效句柄；同时验证原有并发协作/保存与前端 Awareness。Office 持久加载/读取/编辑/关闭通过模拟 Collabora 协议验证，真实 Collabora 仍须部署宏后联调。

### ESC 草稿浮动操作与撤销
接受、拒绝、复制操作栏改为文字上方浮层，桌面按指针悬停位置、移动端按点击位置定位，限制在视口内。本窗口接受的草稿通过 escStreamId 匹配同步事件，以 esc-accept origin 加入 Yjs 本机撤销记录；其他远端编辑仍不进入撤销历史。接受前后独立划分撤销批次，Ctrl+Z 可撤回接受。


### 用户统一撤销记录
文档实时同步事件使用 document-edit origin，用户的 Yjs UndoManager 统一记录本机及远端已提交的用户/AI正文编辑，每次远端编辑前后独立分组；初始化/轮询补全仍使用 server origin，不把整份历史快照加入撤销。撤销增量正常同步给协作者。AI未暴露共享用户撤销记录的入口，不允许借用用户 Ctrl+Z 栈；现有文档工具不提供 undo/redo。浮动草稿工具栏使用图标、语义色、圆角和视口边界定位。
