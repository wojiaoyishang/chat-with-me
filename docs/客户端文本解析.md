# 客户端文本与时间解析约定

统一工具位于 `src/lib/clientText.js`，React 组件位于 `src/components/ClientText.jsx`。消息 tips 的旧文本以及结构化审计中的普通文本 value 已接入组件。

## 后端输出

通过消息 JSON 的 `extraInfo.useTextFormat: true` 声明 tips 需要解析，正文不添加协议前缀。例如：

```json
{"tip":"创建于 {{datetime:2026-10-07T11:06:03.123Z}}", "extraInfo":{"useTextFormat":true}}
```

前端也接受顶层 `useTextFormat`（优先于 extraInfo 中的值）。未提供字段或非 true 值时保持普通文本。结构化审计的普通文本项可设置 `useTextFormat: true`；已有 `format: "datetime"` 的字段直接使用日期工具。

时间采用 ISO 8601，后端新生成值统一以 UTC 的 `Z` 或 `+00:00` 传输；前端兼容显式偏移形式以正确还原时间点。支持秒后小数（最多9位，浏览器精度为毫秒）。缺少时区、无效日期不会被猜测修正。历史无时区值需在确认来源后由专门兼容逻辑处理，本工具不承担数据库历史时间迁移。

## 前端使用

```jsx
<ClientText text={tip} useTextFormat={useTextFormat} />
```

组件还支持 `locale`、`timeZone` 用于测试或明确指定展示区域；业务默认不传，采用浏览器地域和时区。其余属性转交 span。组件不会插入 HTML，不解析 Markdown，也不会递归解析占位符生成的内容。

```js
parseTimestamp('2026-10-07T11:06:03Z'); // Date 或 null
formatLocalTimestamp(value); // 本机时间；无效值默认显示 —
resolveClientText(text); // options.useTextFormat 为 true 才解析占位符
```

非法或未知占位符原样保留。格式化函数可传 `fallback`。结构化 tips 已有 `format: datetime/message_created_at` 时直接走统一时间工具，不需要额外文本标记。普通文本中的时间模板只在显式设置 useTextFormat: true时替换。code/link/badge 等审计格式保留原有语义。

## 范围及验证

后续实现已完成后端时间字段审计、头像菜单移除与实时统计 badge；时间输出统一为 UTC，历史无时区值仍不猜测。后端详细覆盖和计数口径见其 docs/时间与消息统计.md。

运行 `node tests/clientText.test.mjs` 验证JSON 字段启用、时区转换、无时区拒绝、非法日期及普通文本不解析。
