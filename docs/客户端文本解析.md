# 客户端文本与时间解析约定

统一工具位于 `src/lib/clientText.js`，React 组件位于 `src/components/ClientText.jsx`。消息 tips 的旧文本以及结构化审计中的普通文本 value 已接入组件。

## 后端输出

需要解析的文本必须以 `[client-text:v1]` 加真实换行开头。例如 JSON 中：

```json
{"tip":"[client-text:v1]\n创建于 {{datetime:2026-10-07T11:06:03.123Z}}"}
```

换行在 JSON 中编码为 `\n`，解码后必须是实际换行。不要把两个字符反斜杠与 n 直接写进业务字符串。

时间采用 ISO 8601，后端新生成值统一以 UTC 的 `Z` 或 `+00:00` 传输；前端兼容显式偏移形式以正确还原时间点。支持秒后小数（最多9位，浏览器精度为毫秒）。缺少时区、无效日期不会被猜测修正。历史无时区值需在确认来源后由专门兼容逻辑处理，本工具不承担数据库历史时间迁移。

## 前端使用

```jsx
<ClientText text={tip} />
```

组件还支持 `locale`、`timeZone` 用于测试或明确指定展示区域；业务默认不传，采用浏览器地域和时区。其余属性转交 span。组件不会插入 HTML，不解析 Markdown，也不会递归解析占位符生成的内容。

```js
parseTimestamp('2026-10-07T11:06:03Z'); // Date 或 null
formatLocalTimestamp(value); // 本机时间；无效值默认显示 —
resolveClientText(text); // 有首行标记才解析占位符
```

非法或未知占位符原样保留。格式化函数可传 `fallback`。结构化 tips 已有 `format: datetime/message_created_at` 时直接走统一时间工具，不需要额外文本标记。普通文本中的时间模板只在存在显式首行标记时替换。code/link/badge 等审计格式保留原有语义。

## 范围及验证

此版本提供解析基础设施和消息 tips 接入，并不代表全项目时间读写已统一完成。后端时间字段审计、头像菜单移除和实时统计 badge 属于后续原任务范围。

运行 `node tests/clientText.test.mjs` 验证标记启用、时区转换、无时区拒绝、非法日期及普通文本不解析。
