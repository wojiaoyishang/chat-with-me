# 动作模式角色模型

角色模型目录由后端 `application/avatar_scene/catalog.py` 管理，前端复用 GLTFLoader、AnimationMixer 和现有动作窗口，不按角色另写一套场景。

## 当前模型

- `flying-robot`：默认角色，飞行机器人，单个 `Scene` 动画映射为 `idle`（飞行盘旋），只支持 `neutral` 表情。它通过刚性节点动画运动，不需要骨骼皮肤。
- `robot-expressive`：原表情机器人，包含 idle、wave、yes、no、thumbs_up、dance，以及 neutral、angry、surprised、sad。

飞行机器人作者 Shayan，许可 CC BY 4.0。前端模型目录内保存许可说明，场景展示作者与来源链接；GLB 原始署名元数据保持不变。

## 会话选择与保存

复用会话设置的后端 select Schema，字段为 `extra_info.options.avatarModelId`。新建会话保存默认值；旧会话首次读取时补齐默认值，不改变最近活跃排序。不需要数据库结构迁移。

用户在会话设置中切换角色，前端通过经过身份校验的 `avatar.scene.select` 保存 ID，仅能选择后端登记的模型；复用 update_conversation 递归合并，保留其他选项。前端串行保存快速切换，成功后重载当前场景，失败提示并回退；切换不停止聊天或语音。发送消息时后端使用已保存的角色选择，避免旧 options 快照覆盖选择。

`avatar.scene.catalog` 返回该会话保存的完整模型动作目录；未创建会话时允许预览登记模型。`avatar.scene.start` 必须携带目录 modelId/version 和实际加载的动作、表情 ID，后端核对保存的模型及目录。切换废止当前连接的旧场景租约，旧命令不会进入新场景。刷新重新加载默认动作，不回放历史姿势。

AI 动作提示包含当前角色可用的动作与表情；服务校验场景对应的目录，不将没有的动作或表情假装映射到现有动画。延迟语音触发、一次调用、工具结果与日志沿用既有流程。

## 添加其他模型

1. 把 GLB 及来源／许可说明放入前端 `public/models/<模型ID>/`。
2. 后端添加 JSON 目录，在 catalog.py 登记 ID、显示名与文件。asset 使用前端静态路径，pose.clip 必须和 GLB 动画片段名称匹配，expression.morph 必须存在。
3. 所有模型必须提供 `idle` 与 `neutral`，它们用于场景初始状态和非循环动作结束后的恢复。
4. 如果新增工具动作 ID 或表情 ID，同步更新 avatar_set_pose 的 Literal Schema，并加入目录兼容性回归。骨骼与刚性节点动画均可，表情需要真实 morph target。
5. 使用真实 GLTFLoader 检查加载与动画映射，验证会话独立保存、切换后的租约失效及刷新，不新增平行播放器或工具执行流程。

## 本次验证

GLTFLoader 加载两个内置模型、目录与动画映射、飞行模型署名、模型选择保存与恢复、无效模型拒绝、旧场景失效、动作范围限制、控制 ACK、语音反馈和前端构建。
